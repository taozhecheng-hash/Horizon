## [ASML 与蔡司论文探讨超越 0.55 High-NA 的 Hyper-NA EUV 路径](https://semiengineering.com/hyper-na-euv-the-next-extension-beyond-high-na-lithography-carl-zeiss-asml/) ⭐️ 8.0/10

卡尔蔡司 SMT 与 ASML 的研究人员发表了一篇题为《Hyper-NA：数值孔径至少为 0.75 的系统》的技术论文，探讨了超越当前 0.55 数值孔径 High-NA EUV 系统的光刻架构。摘要内容涵盖所提出的光学架构、分辨率潜力、掩模三维效应以及在该更高数值孔径下的偏振行为。 这篇论文表明，共同定义 EUV 光学系统的两家公司已经在探索 High-NA 之后的下一代路线图，这对所有规划 2nm 以下节点的芯片制造商以及整个光刻供应链都具有重要意义。如果 Hyper-NA 最终落地，它将重塑先进图形化的经济性，并把摩尔定律的缩放延伸至当前 High-NA 设备所能达到的范围之外。 该论文瞄准的数值孔径至少为 0.75，远高于当前标准 EUV（NXE）设备的 0.33 数值孔径和 High-NA（EXE）系统的 0.55，摘要还明确把掩模三维效应和偏振列为尚待解决的光学难题。目前公开的只有摘要概要，因此 Hyper-NA 尚没有公布的时间表、成本、产能数据或客户承诺。

rss · SemiEngineering · 10月7日 19:47

**背景**: EUV 光刻利用由激光脉冲锡等离子体产生的 13.5 纳米极紫外光在芯片上印制图形，而 ASML 是这类设备的唯一供应商。数值孔径（NA）衡量光学系统收集和聚焦光线的能力，数值孔径越高，可分辨的特征尺寸越精细，这正是产业界在最关键光刻层从 0.33 数值孔径 EUV 转向 0.55 数值孔径 High-NA（EXE 平台）的原因。Hyper-NA 是所提出的下一步方案，而这类设备的光学元件由 ASML 长期的光学合作伙伴卡尔蔡司 SMT 开发。

## [AMD ROCm 10.1 发布：hipFILE 快速路径、NUMA 内存与 LLVM 24](https://www.storagereview.com/news/amd-rocm-10-1-hipfile-fast-path-numa-memory-llvm-24) ⭐️ 7.0/10

AMD 于 10 月 5 日发布 ROCm 10.1，在新的 AMD Infinity Storage 体系中加入 hipFILE 异步快速路径，并引入 NUMA 感知的主机内存分配、LLVM 24、ROCm CLI 1.0、AMD SMI 以及 WSL2 预览版。本次更新的重点是把数据从存储直接送到 GPU，而不再绕道 CPU 内存。 如今检查点文件、KV 缓存和模型权重经常超出加速器内存容量，因此存储到 GPU 的数据搬运耗时往往比计算本身更主导迭代时间。优化这条路径是 AMD 在 HPC 与 AI 场景中缩小与 NVIDIA CUDA 生态软件差距的关键一环。 hipFILE 提供 C 与 Python API，支持同步、异步和批量 I/O，当直通 GPU 的路径不可用时会自动回退到标准 POSIX I/O；配套的 ais-check 工具会检测内核、驱动、运行时和挂载卷是否满足快速路径要求。该库随 TheRock 一同交付，源码位于 ROCm 的 rocm-systems 仓库中。

rss · StorageReview · 10月7日 15:46

**背景**: ROCm 是 AMD 面向 GPU 计算的开源软件栈，地位相当于 NVIDIA 的 CUDA，每个版本都会打包库、编译器和系统工具。hipFILE 是让应用与 GPU 直接读写数据的 I/O 层；NUMA（非统一内存访问）指服务器中 CPU 内存被划分为访问延迟不同的区域，因此把内存分配到正确的区域对性能很关键。LLVM 是支撑 AMD GPU 与 CPU 工具链的编译器基础设施，而 Infinity Storage 这一品牌指 AMD 用于把 LLM KV 缓存等数据从 GPU HBM 卸载到 NVMe 和 RDMA 网络存储的软件栈。

## [The Next Platform 观点：内存是 IT 与 AI 产业的关键命门](https://www.nextplatform.com/store/2026/10/08/memory-is-the-lynchpin-of-the-it-industry-and-doubly-so-for-ai/5301841) ⭐️ 7.0/10

The Next Platform 发表分析文章，提出内存（而非算力）已成为 IT 产业的核心约束，而对 AI 工作负载与基础设施而言这一约束更加突出。文章把内存带宽与容量视为塑造 HPC、AI 训练与推理系统设计的战略性瓶颈。 如果内存才是真正的瓶颈，那么 AI 供应链的支出重点、芯片路线图与采购决策就会从单纯追求峰值算力转向 HBM、先进 DRAM 和以内存为中心的架构。这会影响从规划集群规模的大型云厂商，到内存厂商和系统设计者的所有参与者。 其核心论据是业界熟知的“内存墙”：算力吞吐的增长速度快于内存带宽，导致大语言模型等 AI 工作负载越来越多地受限于数据搬运而非算术运算。该文属于定性评论，而非新的基准测试或产品数据，因此其具体论断更适合作为分析框架而非实测结论来理解。

rss · The Next Platform · 10月8日 02:39

**背景**: 高性能计算（HPC）传统上通过并行工作的强大处理器集群来解决复杂的科学与工程问题。随着 AI 模型规模扩大，单位计算所对应的数据搬运量急剧上升，形成了“内存墙”——处理器因等待数据而空转。将 DRAM 裸片堆叠在 GPU 附近的高带宽内存（HBM）成为主要解决方案，HBM 需求也随模型规模一同增长。
